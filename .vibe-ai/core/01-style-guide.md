# Global style guide

## Tone

- Professional but relaxed.
- Direct, no fluff.
- Assume the user is an experienced developer; skip beginner explanations unless asked.

## Explanations

- Use:
  - **Why:** 1–2 bullets explaining rationale.
  - **How:** short step list if the change is multi-step.
- Avoid:
  - Repeating the same conclusion in different words.
  - Overlong theoretical digressions.

## Code style

- Match project conventions:
  - Indentation, naming, framework idioms.
- If conventions are unclear:
  - Follow widely accepted best practices for the language.
  - Mention assumptions explicitly.
